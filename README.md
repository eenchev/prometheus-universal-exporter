Turn a source that was never meant for Prometheus — an HTTP API, a gRPC service, a Graphite server, a file on this or another host or in an S3 bucket, a SQL database, a Redis server, a DNS name, a TLS certificate, a Kubernetes object — into a Prometheus target, without writing an exporter for it.

The exporter can collect metrics from almost any source: HTTP services returning JSON, NDJSON, YAML, TOML, INI, XML, CSV, HTML, logfmt, plain text, or Prometheus exposition; gRPC services; Graphite servers; local files such as .prom files generated by batch jobs; the same files on another host, read over SSH; objects in Amazon S3 or a store that speaks its API, in a build that asks for them; SQL databases such as MySQL, PostgreSQL, and SQL Server; the INFO and read-only commands of Redis and Valkey servers, in a build that asks for them; the DNS records of a name; the TLS certificates a server presents, with their expiry; or Kubernetes objects of any kind, built in or custom, listed from the API server. Collectors define how to query, parse, transform, and publish the data as Prometheus metrics. Because everything is configuration-driven, collection rules can be changed without writing code, rebuilding the exporter, or redeploying it.

## How it works

Targets are never written into the configuration. Prometheus discovers the real
service and passes it to the exporter as `target`; the `collector` parameter
picks which server-side configuration reads it:

```text
/probe?target=http%3A%2F%2Flegacy.example%3A8080&collector=legacy_text
```

One exporter therefore serves many services and many response shapes, and a
collector is reusable across every target that answers the same way.

For a fixed list of targets there is a second way in: list them as
[static targets](docs/STATIC-TARGETS.md), which the exporter scrapes itself on
their own intervals and serves together on one endpoint, `/static-targets`, for
Prometheus to scrape like any other exporter, and, one by one, over OTLP.

## Quick start

Describe a collector:

```yaml
collectors:
  - name: app_json
    metrics_prefix: myapp   # optional; exports myapp_application_requests_total
    request:
      type: http
      path: /status
    transform:
      type: jq
    metrics:
      - name: application_requests_total
        description: Total application requests
        type: counter
        expression: .requests
```

`metrics_prefix` is optional: when set, it is joined with `_` to the front of
every metric the collector exports. See
[Prefixing a collector's metrics](docs/CONFIGURATION.md#prefixing-a-collectors-metrics).
For a list of things — servers, rows, components — give a metric `items` and
write its value and labels against one item at a time; see
[Metrics per item](docs/CONFIGURATION.md#metrics-per-item). A paged API is read
page by page into one answer; see [Pagination](docs/REQUESTS.md#pagination).
Collectors can also live in files of their own, listed under `collector_files`
— one per team or per ConfigMap key; a collector name must be unique across all
of them. See [Collector files](docs/CONFIGURATION.md#collector-files).

Your editor can check the file as you type: start it with

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/eenchev/prometheus-universal-exporter/main/configs/config.schema.json
```

and the YAML language server completes keys and flags mistakes against
[`configs/config.schema.json`](configs/config.schema.json). Every expression is also compiled
when the exporter starts, so a typo stops it with a message naming the
collector and metric, rather than failing each scrape.

Run the exporter and probe a target through it:

```sh
go run . --config.file=configs/config.example.yaml

curl 'http://localhost:8080/probe?target=http://127.0.0.1:9000&collector=app_json'
```

The response is ordinary Prometheus exposition, which is what Prometheus
scrapes. `configs/config.example.yaml` is a complete working
document with JSON, text, CSV and Prometheus collectors, over HTTP and local
files; the other decoders have their examples under `examples/` and in
[Configuration](docs/CONFIGURATION.md).

Or run the published image:

```sh
docker run -p 8080:8080 \
  -v "$PWD/config.yaml:/etc/prometheus-universal-exporter/config.yaml:ro" \
  ghcr.io/eenchev/prometheus-universal-exporter:latest
```

## Install with Helm

The chart is published to GitHub Container Registry as an OCI artifact. It is public, so no registry login is needed. Prometheus Operator CRDs are not installed by this chart.

```sh
helm install exporter \
  oci://ghcr.io/eenchev/charts/prometheus-universal-exporter \
  --version 1.6.0 \
  --set-file 'config.data.config\.yaml=configs/config.example.yaml'
```

Omitting `--version` takes the newest published chart; pin it for anything you deploy more than once. To install from a checkout instead:

```sh
helm install exporter charts/prometheus-universal-exporter \
  --set-file 'config.data.config\.yaml=configs/config.example.yaml'
```

The chart creates the Deployment, Service, ConfigMap and, on request, `ServiceMonitor` or `PodMonitor` resources with the relabeling the probe pattern needs. With `allocator.enabled` it also runs the [target allocator](docs/ALLOCATOR.md), which shares the targets out across exporter replicas so collection scales horizontally. See the [chart README](charts/prometheus-universal-exporter/README.md) for its values.

## Endpoints and flags

`/probe` scrapes a target through a collector, `/self-metrics` serves the
exporter's own metrics and `/static-targets` the latest results of the static
targets. `/` is a landing page, `/collectors` probes a target from the browser,
and `/health` and `/ready` are for Kubernetes; `/-/reload` and `/debug` are
served when their flags ask for them. [Endpoints](docs/ENDPOINTS.md) has what
each one takes and answers, and [Command-line flags](docs/FLAGS.md) every flag,
which `--help` prints too.

- [Configuration](docs/CONFIGURATION.md) — collectors, decoders, transforms, metric rules, caching and serving the last good result while a target is down, environment variables, reloading.
- [Endpoints](docs/ENDPOINTS.md) and [command-line flags](docs/FLAGS.md) — what each endpoint takes and answers, and every flag of the exporter.
- [Target requests](docs/REQUESTS.md) — the request URL and the `Host` header, redirects, HTTP/2, retries, accepted statuses, pagination, restricting targets, TLS, proxies, per-scrape overrides.
- [Local files](docs/LOCALFILE.md) — the `localfile` request type: reading metrics and status files from disk, one file or a whole directory.
- [Graphite](docs/GRAPHITE.md) — the `graphite` request type: Graphite series from a render API, or carbon lines from a file, as Prometheus metrics.
- [gRPC](docs/GRPC.md) — the `grpc` request type: a unary gRPC method called with a JSON message, its answer mapped as JSON, with message types from server reflection, a descriptor set or `.proto` files.
- [Files over SSH](docs/SSHFILE.md) — the `sshfile` request type: metrics and status files read from another host over SFTP, one file or a whole directory, on a kept connection with the host's key always verified.
- [Objects in S3](docs/S3FILE.md) — the `s3file` request type, in a build that asks for it: objects of Amazon S3, MinIO, Ceph, R2 or GCS read as files, one object or every matching one under a prefix.
- [Databases over SQL](docs/SQL.md) — the `sql` request type: one read-only statement on PostgreSQL, MySQL, SQL Server and, built on request, Oracle, ClickHouse, Snowflake or Vertica, its rows read by column, on pooled connections.
- [Redis and Valkey](docs/REDIS.md) — the `redis` request type, in a build that asks for it: a server's INFO and the replies of read-only commands, such as a queue's length, as a JSON document, over plaintext or TLS.
- [DNS](docs/DNS.md) — the `dns` request type: the A, AAAA, CNAME, MX, NS, TXT, SRV or PTR records of a name, from the system's resolver or a named server, as a JSON document.
- [TLS certificates](docs/TLSCERT.md) — the `tlscert` request type: the certificates a server presents in a TLS handshake, their names, issuers and expiry, and whether the chain verifies.
- [Kubernetes objects](docs/KUBERNETES.md) — the `kubernetes` request type: the objects of one resource, built in or custom, listed from the API server with the exporter's service account, as a JSON document, for metrics such as kube-state-metrics gives from configuration alone.
- [Authentication](docs/AUTHENTICATION.md) — credentials for the target, logging in to it, and credentials for the exporter itself.
- [Prometheus Operator](docs/PROMETHEUS-OPERATOR.md) — ServiceMonitor and PodMonitor.
- [Helm chart](charts/prometheus-universal-exporter/README.md) — every chart value.

- [Self-metrics](docs/SELF-METRICS.md) — what the exporter reports about itself.
- [Static targets](docs/STATIC-TARGETS.md) — targets the exporter scrapes itself on their own intervals and serves on one endpoint.
- [Target allocator](docs/ALLOCATOR.md) — `pue-allocator`, which serves several exporter replicas their configuration and each its share of the static targets, and Prometheus the probe targets already pointed at a replica.
- [OTLP](docs/OTLP.md) — OTLP export, its retries and compression.
- [Logging](docs/LOGGING.md) — the log format.
